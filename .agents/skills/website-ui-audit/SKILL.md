# Website UI Audit

1. Determine the stack, how to install/run/build/test, CSS architecture and existing component library.
2. Locate all route definitions, layouts, shared components, theme values, assets and major interactive workflows.
3. Make a page/feature inventory: page, purpose, audience, key UI, current issues, protected behavior.
4. Identify existing reusable UI patterns; detect inconsistencies in typography, spacing, colors, responsive behavior, navigation, forms, empty states and loading states.
5. If a browser or screenshot capability is available, inspect representative pages at mobile (~375px), tablet (~768px) and desktop (~1440px). Do not pretend to have inspected screenshots if unavailable.
6. Record technical constraints (API contracts, auth, i18n, forms, SEO, existing app state).
7. Produce a concise redesign plan and prioritization. Then proceed to implementation without unnecessary approval loops.
